# 模型选型矩阵

平台按「重活用强模型、轻活用快模型」的原则为不同角色分配模型。选型依据是任务密度：判定与提炼类内部调用追求低延迟，交付类调用追求质量。

## 当前矩阵

| 角色 | 模型 | 选型理由 |
|---|---|---|
| 路由判定 | qwen3.8-27b | 只发 system 与 user 的轻量调用，要求短读超时快速返回 |
| 常规直答 | qwen3.7-flash | 会话默认模型，延迟与成本均衡 |
| 编排子任务 | qwen3.8-max / deepseek-v4-pro | 按专家分档配置，交付质量优先 |
| 聚合节点 | 与专家同档 | 需要消化多路材料后成稿 |
| 用户画像提炼 | qwen3.8-27b | 离线批处理，对延迟不敏感 |
| 嵌入 | text-embedding-v4 | 1024 维，OpenAI 兼容端点 |

## 更换模型的注意事项

一，端点地址以 model_provider 表为准，API Key 经环境变量注入不落库。二，更换嵌入模型必须同步确认向量维度，维度变化需删除向量表重建。三，agent 表为每个智能体独立指定模型，改库即时生效，无需重启。四，qwen3 系列为按需思考模式，简单请求可能跳过思考，属模型正常行为，与平台的思考透传开关无关。

## DeepSeek 与通义的分工

DeepSeek 系列用于编排子任务与聚合等交付型调用；通义系列覆盖路由判定、直答、画像提炼与嵌入。两条线均走 OpenAI 兼容协议，新增供应商只需设置对应环境变量。
